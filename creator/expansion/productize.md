# 확장 — 이 노하우를 다른 파이프라인으로

> "이게 제대로 자리잡히면 이 노하우로 다른 수익화 콘텐츠나 사업기획도 파이프라인으로 세팅하고 싶다"
> 는 목표에 대한 설계입니다. **1단계가 안정되기 전에는 손대지 마세요.**

## 전제 조건 (이걸 만족하기 전엔 확장 금지)

- [ ] 주 3편 발행을 **12주 연속** 유지
- [ ] 저장률 1% 이상이 안정적
- [ ] 협찬 3건 이상 완주 (단가·계약·정산 경험)
- [ ] `ops/kpi-log.csv` 에 12주치 데이터 축적

이 넷이 채워지면 "운이 좋았던 것"과 "재현 가능한 것"이 구분됩니다.
**재현 가능한 것만 파이프라인이 됩니다.**

## 재사용 가능한 자산이 무엇인지 정확히 알기

이 저장소에서 만들어진 것 중 **다른 분야에 그대로 옮겨지는 것**은 이렇습니다.

| 자산 | 육아 계정에서 | 다른 분야로 옮기면 |
|---|---|---|
| **3층 구조** (정체성/성장엔진/시그니처) | 복직맘 / 나들이정보 / 수달이네 | 어떤 주제든 동일하게 적용 |
| **참여 장치 세트** (저장·공유·댓글·DM 트리거) | `strategy/02-growth-engine.md` | 주제 무관, 그대로 |
| **제작 파이프라인** (prep → EDL → 자막 → 본문) | `pipeline/` | 영상 콘텐츠 전부 |
| **포맷 5종** (F1~F5) | `playbooks/short-reels.md` | 소재만 바꾸면 동작 |
| **운영 루틴** (재고 2편, 촬영/편집 분리) | `ops/weekly-routine.md` | 주제 무관 |
| 훅 라이브러리 | 육아 맥락 전용 | 재작성 필요 |
| 소재 은행 | 0~2세 전용 | 재작성 필요 |

즉 **7개 중 5개가 그대로 이식됩니다.** 새 분야를 시작할 때 드는 비용은
"훅 라이브러리 + 소재 은행 재작성"뿐이고, 이건 하루 작업입니다.

## 확장 경로 3가지

### 경로 A. 같은 관객, 다른 상품 (가장 빠름)
이미 확보한 "0~3세 자녀를 둔 25~34세 부모"에게 다른 걸 파는 것.

1. **공동구매** — 협찬으로 검증된 제품을 직접 사입/위탁 판매. 마진 15~30%
2. **디지털 상품** — "0~2세 나들이 장소 100곳 노션 DB", "복직 준비 체크리스트"
   → 원가 0, 한 번 만들면 계속 팔림. **첫 자체 상품으로 가장 안전**
3. **클래스** — "직장 다니며 육아 계정 키우기" (이 저장소가 곧 커리큘럼)

### 경로 B. 같은 노하우, 다른 주제 (계정 복제)
파이프라인을 그대로 들고 다른 카테고리로.

- 후보 판단 기준: ① 검색 수요가 있는가 ② 검증이 필요한 영역인가 ③ 내가 실제 당사자인가
- 세 번째가 핵심입니다. 당사자가 아니면 2층(정보 검증)의 신뢰가 안 생깁니다.
- 실행: `creator/` 를 통째로 복사 → `strategy/`, `playbooks/hooks.md`, 소재 은행만 재작성

### 경로 C. 노하우 자체를 상품화 (가장 늦게)
- 다른 부모 계정 컨설팅 / 대행
- 이 파이프라인을 도구로 패키징
- **조건**: 본인 계정 성과가 증명된 뒤에만. 안 그러면 파는 게 아니라 파는 척이 됩니다.

「수달이네」가 자리 잡으면 아이 얼굴 노출과 무관하게 굴러가는 자산이 됩니다.


이 경로의 장점: **아이가 커서 노출을 원치 않게 되어도 사업이 계속됩니다.**
`strategy/05-child-safety.md` 의 장기 리스크에 대한 실질적인 답이기도 합니다.

## 파이프라인화의 실제 의미

"파이프라인으로 세팅한다"는 건 자동화가 아니라 **의사결정을 미리 해두는 것**입니다.

이 저장소가 하는 일이 정확히 그거예요.
- 뭘 찍을지 → 샷 리스트가 정해져 있음
- 어떤 포맷으로 만들지 → F1~F5 중 선택 규칙이 있음
- 훅은 뭘로 → 라이브러리에서 고름
- 언제 올릴지 → 편성표가 있음
- 잘됐는지 어떻게 아는지 → 지표 판단 규칙이 있음

새 분야로 갈 때 복사하는 건 파일이 아니라 **이 결정들의 구조**입니다.
