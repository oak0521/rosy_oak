# 경쟁사 비교 (네이버 모바일 검색 캡처) — 수집·반영 방법

`weekly-report.html`의 **#serp "경쟁사 비교"** 섹션은 `const SERP = {…}`에 데이터가 있을 때만 나타난다(브랜드별로 비어 있으면 섹션·메뉴 모두 숨김).
이 데이터는 **사용자가 네이버 모바일 검색 결과를 직접 캡처해서 보내 주면** 세션이 값을 옮겨 적고 썸네일을 잘라 넣는다.
클라우드 세션은 네이버에 접속할 수 없고(프록시 403) 사용자 크롬에도 연결되지 않으므로 세션이 직접 캡처할 수 없다.

## 사용자가 보낼 것 (키워드 1개당)
1. 네이버 **모바일 앱/모바일 웹**에서 키워드 검색 (로그인 없이, 광고는 클릭하지 않기 — 클릭 비용 발생)
2. 아래 영역이 보이도록 **스크린샷 2~4장** (위→아래로 이어지게, 겹쳐도 됨)
   - 파워링크(광고) 영역 전체
   - 쇼핑 영역: 상품 썸네일·가격·평점·리뷰 수·구매(찜) 수·'AD' 표시가 **글자 읽힐 정도**로 보이는 것
3. 우리 제품(아넬라/로지오가닉)이 보이는 위치가 한 장에 포함되게
4. 키워드와 캡처 시각을 파일명이나 메시지에 적기 (예: `아기퓨레_1110.png`)

키워드 우선순위는 `../keyword-weekly/competitor_seed_keywords.md` 표(매출 상위 전환 키워드 → 순위 밀리는 키워드) 순서. 처음엔 브랜드별 3~5개면 충분.
같은 키워드를 2~3회 새로고침하면 파워링크 로테이션을 볼 수 있지만 한 번이어도 된다(리포트에 "캡처 시점 한정"으로 표기됨).

## 세션이 하는 일
1. 캡처를 눈으로 열어 값 판독 → `input.json` 작성 (**화면에 보이지 않는 값은 비워 둔다, 추정 금지** — 가격·리뷰·구매 수는 이 리포트에서 가장 쉽게 틀리는 숫자)
2. 상품 이미지 영역 좌표(`crop`)를 지정해 썸네일 생성:
   ```bash
   cd reports/analysis/serp-compare
   NODE_PATH=$(npm root -g) node make_serp.js input.json out.json
   ```
   스키마와 필드 설명은 `make_serp.js` 상단 주석. 출력 JSON 한 줄을 `weekly-report.html`의 `const SERP = {…};`에 그대로 붙여 넣는다.
3. 반영 전 확인: 값 몇 개를 캡처와 다시 대조, `node --check` + Chromium 렌더(`#serp` 카드·막대·표·원본 캡처 확대) + 390px 가로 스크롤 없음.
4. `reports/analysis/serp-compare/YYYY-MM-DD/`에 `input.json`만 보관한다. **원본 캡처 PNG는 저장소가 공개라 커밋하지 않는다**(리포트에는 축소본이 들어가므로 공개 여부를 사용자에게 한 번 확인).

## 화면 구성 (#serp)
- 키워드 탭 → 요약 칩 4개(우리 최고 순위 / 가격·단가 vs 경쟁 중앙값 / 리뷰 수 vs 경쟁 중앙값 / 광고 슬롯 수)
- 노출 상품 카드(순위순, 썸네일·브랜드·가격·단가·평점·리뷰·구매, 우리 제품은 진한 테두리)
- 지표 1개를 한 축으로 비교하는 막대(가격 / 단가 / 리뷰 수 / 구매 수 토글)
- 비교표 + 원본 캡처(클릭하면 확대)

## 해석 시 주의
- 파워링크·쇼핑 노출은 광고 로테이션·개인화·시간대에 따라 바뀐다 → 한 번의 캡처는 대표성이 약하다.
- 단가(100g당 등)는 모든 상품에 화면 표기가 있을 때만 비교에 쓰고, 아니면 가격으로 비교한다. 용량이 다른 상품의 가격 비교는 오해를 부르므로 단가 표기를 우선 캡처한다.
- 구매 수·리뷰 수는 누적값이라 출시 시기가 다른 상품끼리의 비교에는 한계가 있다(신제품은 항상 불리).
