# 경쟁사 비교 (네이버 모바일 검색) — 수집·반영 방법

`weekly-report.html`의 **#serp "경쟁사 비교"** 섹션은 `const SERP = {…}`에 데이터가 있을 때만 나타난다(브랜드별로 비어 있으면 섹션·메뉴 모두 숨김).
우리 제품과 함께 노출되는 경쟁 상품의 **썸네일·가격·단가·평점·리뷰 수·구매 수·순위·광고 여부**를 카드/막대/표로 비교한다.

## 방법 A (기본, 자동) — `capture_serp.js`
환경 네트워크 정책이 네이버 도메인(`m.search.naver.com`, `search.shopping.naver.com`, `shopping.naver.com`, `*.pstatic.net`)을 허용해야 한다(기본 차단 → 403).
```bash
cd reports/analysis/serp-compare
W=/tmp/serp-work            # 작업 폴더(저장소 밖). 이미지·캡처가 들어가므로 커밋하지 않는다
NODE_PATH=$(npm root -g) node capture_serp.js keywords.json $W          # 모바일 SERP 수집 → $W/input.json (+ img/, shots/)
NODE_PATH=$(npm root -g) node make_serp.js $W/input.json $W/out.json    # 썸네일 160px·캡처 400px 축소 → out.json
# out.json 한 줄을 weekly-report.html 의 `const SERP = …;` 에 그대로 붙여 넣는다
```
- `keywords.json`: `{ "anela": [...], "rosy": [...] }` — 우선순위는 `../keyword-weekly/competitor_seed_keywords.md`(매출 상위 전환 키워드 → 순위 밀리는 키워드). 현재 브랜드별 5개.
- 수집 항목: **파워링크**(광고주·제목·URL·문구, 최대 5) / **쇼핑광고**(광고 상품 카드, 최대 6) / **쇼핑**(일반 상품 카드, 최대 8) + 상위 밖이라도 **우리 제품**(최대 6). 카드마다 판매처·가격·단가(g/ml 100단위 환산)·평점·리뷰·구매·프로모션 문구·썸네일.
  - 순위는 영역별(파워링크/쇼핑광고/쇼핑)로 따로 센다. 일반 쇼핑 카드 중 **카탈로그형**은 판매처가 "가격비교(판매처 N곳)"로 표시된다.
  - 구매 `2천+`, 리뷰 `2.8만` 같은 표기는 `buysTxt`/`reviewsTxt`로 보존하고 숫자(`buys`/`reviews`)는 하한 환산값 — 화면에는 표기 그대로 나온다.
- **광고는 클릭하지 않는다**(클릭 비용 발생). 페이지 로드만 하며 키워드당 1회만 연다(광고 노출수에 1회씩 잡힐 수 있음). 키워드 사이 2.5~4.5초 대기.
- 수집 파라미터: `--max-ad 6 --max-org 8 --max-pl 5`. **리포트 용량**: 키워드 10개 ≈ 3.2MB(리포트 총 ≈ 13MB, 한도 16MB) — 키워드를 늘리면 먼저 용량을 확인한다. 주마다 `SERP`를 교체하므로 누적되지 않는다.
- 한계: ① 해외 클라우드 IP·비로그인·비개인화 화면이라 한국 소비자 화면·광고 구성과 다를 수 있다(방법 B가 더 정확). ② 클래스명이 해시라 네이버가 DOM을 바꾸면 파서가 깨질 수 있다
  (안정적인 `data-nlog-area`·`.site`·`.tit`와 innerText 토큰 규칙을 사용, 파싱 실패 시 경고 출력) — 값 몇 개를 화면과 직접 대조한다. ③ 자동 수집이 네이버 약관에 걸릴 수 있어 소량·저빈도로만 쓴다.
- 캡차/차단이 뜨면 해당 키워드는 건너뛰고 경고를 낸다. 우회하지 않는다.

## 방법 B (수동) — 사용자가 직접 캡처
클라우드에서 네이버가 막혀 있거나 한국 IP 기준 화면이 필요할 때. 사용자가 네이버 모바일 검색 스크린샷(파워링크·쇼핑 영역, 가격·평점·리뷰·구매가 읽히게 2~4장, 우리 제품 위치 포함)을 보내면
세션이 값을 눈으로 읽어 `input.json`을 쓰고(**보이지 않는 값은 비운다, 추정 금지**), 상품 이미지 영역 좌표 `crop`을 지정해 `make_serp.js`로 변환한다. 스키마는 `make_serp.js` 상단 주석.
원본 캡처 PNG는 저장소가 공개라 커밋하지 않는다.

## 화면 구성 (#serp)
- 키워드 탭 → 요약 칩 4개(우리 노출 순위(영역별 최고) / 단가 또는 가격 vs 경쟁 중앙값 / 리뷰 수 vs 경쟁 중앙값 / 광고 슬롯 수)
- 노출 상품 카드(파워링크는 문구 카드, 쇼핑은 썸네일·판매처·가격·단가·평점·리뷰·구매, 우리 제품은 진한 테두리)
- 지표 1개를 한 축으로 비교하는 막대(가격 / 단가 / 리뷰 수 / 구매 수 토글) + 비교표 + 원본 캡처(클릭하면 확대)

## 해석 시 주의
- 파워링크·쇼핑광고는 광고 로테이션·개인화·시간대에 따라 바뀐다 → 한 번의 수집은 대표성이 약하다("수집 시점 한정"으로 표기됨).
- 단가는 같은 단위(예: 100g당)를 가진 상품이 3개 이상일 때만 비교에 쓰고, 아니면 가격으로 비교한다(구성이 달라 참고용). 서로 다른 제품군이 섞인 키워드(예: 아기간식)의 중앙값은 거친 지표다.
- 구매·리뷰 수는 누적값이라 출시 시기가 다른 상품끼리의 비교에는 한계가 있다(신제품은 항상 불리). 구매 수는 네이버가 구간(`2천+`)으로만 보여 주는 값이 많다.
- 판매처가 쿠팡·타사 스토어인 "우리 제품"(예: 아넬라 상품명의 쿠팡 판매, 로지오가닉 상품이 아넬라 스토어에서 별도 가격으로 판매)은 `ours`로 표시되지만 공식 판매처인지는 별도 확인이 필요하다.
